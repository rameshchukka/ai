# GraphRAG — PDF Knowledge Base

A simple **RAG (Retrieval-Augmented Generation)** app. You upload PDFs, the app
stores them in a **Neo4j** graph database as vectors. Text is turned into vectors
by a **local HuggingFace model** (`all-mpnet-base-v2`, no API calls), and answers
are generated by **Google Gemini** using only the text found in your PDFs. You can
score the quality of each answer with **RAGAS**.

```
PDF  ─►  chunks  ─►  embeddings  ─►  Neo4j (vector store)
                                          │
question ─► embedding ─► search top-K ────┘─► Gemini answer ─► (optional) RAGAS score
```

---

## 1. How the code is organised

Each file does one job. Read them in this order to understand the flow:

| File | What it does |
|------|--------------|
| `config.py` | Loads settings and API keys from the `.env` file. |
| `pdf_processor.py` | Reads a PDF and splits its text into small **chunks**. |
| `embeddings.py` | Turns text into **embeddings** (number lists) using a **local** HuggingFace model (no API calls). |
| `vector_store.py` | Saves chunks + embeddings in **Neo4j** and searches them. |
| `response_generator.py` | Builds a prompt from the chunks and asks **Gemini** for an answer. |
| `validator.py` | Scores an answer's quality with **RAGAS** metrics. |
| `rag_orchestrator.py` | The "manager" that connects all the pieces above. |
| `app.py` | The **Gradio** web UI (upload, query, validate, manage). |

### The orchestrator ties it together

`rag_orchestrator.py` is the heart of the app. It exposes 4 simple actions that
the UI calls:

- `process_and_store_pdf(pdf)` → chunk → embed → store in Neo4j
- `query(question)` → embed question → search Neo4j → generate answer
- `get_database_info()` → how many documents / chunks are stored
- `delete_document(name)` → remove a document

## 2. What happens, step by step

**Uploading a PDF**
1. `PDFProcessor` extracts text and splits it into chunks (paragraphs).
2. `EmbeddingGenerator` converts each chunk into an embedding vector.
3. `VectorStore` saves each chunk + its embedding into Neo4j.

**Asking a question**
1. The question is converted into an embedding.
2. `VectorStore` finds the **top-K** most similar chunks (cosine similarity).
3. `ResponseGenerator` puts those chunks into a prompt and Gemini writes an
   answer that cites the sources.

**Validating an answer (RAGAS tab)**
1. The app runs a normal query (steps above).
2. `RAGValidator` scores the answer:
   - **Faithfulness** & **Answer Relevancy** — always computed.
   - **Context Precision** & **Context Recall** — only when you provide a
     reference (correct) answer.

### Validation without a reference (ground truth)

A reference is just the "answer key" you write by hand — needed only to grade
context against a known-correct answer. You don't always have one (e.g. live
production questions). What you can still measure without it:

- **Faithfulness** — is the answer grounded in the retrieved chunks?
- **Answer Relevancy** — does the answer address the question?
- **Context Precision (reference-free)** — were the retrieved chunks relevant?
  The LLM judges them against the question/answer instead of a reference.

Only **Context Recall** truly needs a reference (you can't measure "what's
missing" without knowing the full correct answer). So in production: run the
three reference-free metrics live, and keep Recall for an offline test set of
hand-written `{question, reference}` pairs.

## 3. Setup

### Prerequisites
- **Python 3.10+**
- A running **Neo4j 5.x** database (Neo4j Desktop or Docker). Vector search
  works best on Neo4j 5.14+.
- A **Google Gemini API key** → https://aistudio.google.com/apikey

### Install
```bash
pip install -r requirements.txt
```
> The first run downloads the local embedding model `all-mpnet-base-v2`
> (a few hundred MB). After that it loads instantly from cache, offline.

### Configure
Create a file named `.env` in this folder:
```env
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_neo4j_password
NEO4J_DATABASE=graphragdb

GEMINI_API_KEY=your_gemini_api_key
```

---

## 4. Run

```bash
python app.py
```

Then open the URL shown in the terminal (default: http://localhost:7860).

### Using the app
1. **Upload Documents** — upload a PDF and click *Process PDF*.
2. **Query Knowledge Base** — type a question and click *Search*.
3. **Validate (RAGAS)** — ask a question and get quality scores. Add a
   reference answer to also see Precision & Recall.
4. **Manage Database** — see indexed documents or delete one.
5. **System Info** — view the current configuration.

---

## 5. Settings you can change

All defaults live in `config.py`:

| Setting | Default | Meaning |
|---------|---------|---------|
| `embedding_model` | `all-mpnet-base-v2` | Local HuggingFace embedding model (768-dim, no API calls) |
| `generation_model` | `gemini-2.5-flash` | Gemini model that writes answers |
| `chunk_min_length` | `20` | Ignore chunks shorter than this (chars) |
| `top_k_results` | `5` | How many chunks to retrieve per question |
| `max_retries` | `3` | Retries when Gemini hits a rate limit |

---

## 6. Troubleshooting

- **`NEO4J_PASSWORD not set` / `GEMINI_API_KEY not set`** — check your `.env` file.
- **Can't connect to Neo4j** — make sure the database is running and `NEO4J_URI`
  is correct.
- **Empty / "No relevant information found"** — upload a PDF first, or increase
  *Top-K*.
- **Rate limit (429) errors** — the app retries automatically; wait a moment or
  reduce how often you query.
