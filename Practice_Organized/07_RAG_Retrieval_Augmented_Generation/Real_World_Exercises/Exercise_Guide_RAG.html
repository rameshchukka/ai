📘 Concept Notes

Why RAG exists

LLMs only know what they were trained on and can confidently make things up (hallucinate). RAG grounds answers in your actual documents by retrieving relevant chunks and forcing the model to answer using only that context.

The pipeline shape

Ingest documents → split into chunks → embed each chunk → store in a vector index → at query time, retrieve the most similar chunks → build a prompt that clearly separates 'context' from 'question' → generate.

Grounded prompting

The prompt must instruct the model to answer *only* from the provided context and to say 'I don't know' if the answer isn't there — this single instruction is your first and most important hallucination guardrail.

A similarity threshold as a guardrail

If the best-retrieved chunk's similarity score is very low, that's a signal the knowledge base doesn't contain the answer — skip generation and return a clear 'I don't know' instead of risking a hallucinated answer.

💡 Tips & Pitfalls

Tips

  • Always instruct the model to decline if context doesn't contain the answer.
  • Use chunk overlap (10-20%) so answers near chunk boundaries aren't cut off.
  • Retrieve more chunks than you think you need (k=5-8); let the model filter relevance.

Common Pitfalls

  • Chunking mid-sentence/mid-table and losing meaning.
  • Not testing 'no answer exists' questions — a good RAG system should decline, not invent one.
  • Stuffing too much context and burying the actually-relevant chunk.
