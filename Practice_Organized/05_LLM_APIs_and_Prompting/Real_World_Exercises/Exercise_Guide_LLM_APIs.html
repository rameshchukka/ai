📘 Concept Notes

Why prompts need explicit format instructions

An LLM will produce plausible-looking but inconsistently-formatted text unless you explicitly specify the output shape (e.g. 'respond with ONLY valid JSON'). Never assume the model will infer format from context alone.

Few-shot prompting

Showing 2-4 example input→output pairs in the prompt itself often produces more reliable, consistent formatting than long written instructions — the model pattern-matches the examples.

Context window management

Conversation history must be resent on every call — nothing is 'remembered' for free. Long conversations need summarization or truncation strategies to control cost and stay within context limits.

Resilience

Real APIs fail transiently (timeouts, rate limits). Production code always wraps calls in retry logic rather than assuming every call succeeds.

💡 Tips & Pitfalls

Tips

  • Be explicit about output format — 'respond with ONLY valid JSON, no prose'.
  • Lower temperature (0-0.3) for factual tasks; higher (0.7+) for creative tasks.
  • Log prompts and responses during development — you can't debug what you can't see.

Common Pitfalls

  • Vague prompts producing inconsistent output shape across calls.
  • Assuming the model 'remembers' earlier calls without resending history.
  • Not handling rate limits/timeouts — a demo that works once and breaks under load.

🌍 Real-World Use Cases
