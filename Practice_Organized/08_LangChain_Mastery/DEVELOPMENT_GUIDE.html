How to set up your local desktop to develop and run everything in this bundle — Python, a virtual environment, keys, editors, and the provider choices that matter on your org network. Read this once; the per-folder guides assume it.

01 Python & a virtual environment

Use Python 3.10–3.12 in a dedicated venv

LangChain needs 3.10+; 3.12 is a safe choice. Never install into system Python. One shared venv for this whole bundle is fine.

macOS

python3.12 -m venv ~/lc_env
source ~/lc_env/bin/activate
python -V   # should say 3.12.x

Windows (PowerShell)

py -3.12 -m venv %USERPROFILE%\lc_env
%USERPROFILE%\lc_env\Scripts\Activate.ps1
python -V

A handy alias (mac, add to ~/.zshrc): alias lc='source ~/lc_env/bin/activate'.

02 Install dependencies

  1. Activate the venv (you'll do this every session).
  2. Install the base stack: 
    pip install langchain langchain-community langchain-openai langchain-google-genai langchain-anthropic \
  chromadb faiss-cpu sentence-transformers python-dotenv pandas jupyter
  3. For folders with a requirements.txt, prefer that: pip install -r requirements.txt.
  4. For the Postgres exercises also: pip install psycopg2-binary pgvector.

pip on macOS quirk

If pip complains about an externally-managed environment, you're outside the venv — activate it first. Inside a venv you never need --break-system-packages.

03 API keys & the .env pattern

Never hardcode or commit keys

Two folders in this bundle originally shipped live keys (now emptied). Always keep keys in a .env that is git-ignored, and load them with python-dotenv.

# .env  (never commit this)
GOOGLE_API_KEY=your-key
OPENAI_API_KEY=your-key
ANTHROPIC_API_KEY=your-key
HUGGINGFACEHUB_API_TOKEN=your-token
# in code
from dotenv import load_dotenv
load_dotenv()          # reads .env into environment
import os; key = os.getenv("GOOGLE_API_KEY")

Add a .gitignore with .env and __pycache__/ before you ever git init.

04 The org-network reality (important for you)

ComponentOn the org network
Your in-house models (03_Core_and_Extensions)✅ work — designed for it
Local models (HuggingFace local, sentence-transformers)✅ once downloaded (first download needs a network that allows HuggingFace)
Chroma, FAISS, local Postgres✅ fully local
OpenAI / Google / Anthropic APIs⚠ may be blocked — use a personal network or your in-house wrapper
HuggingFace Hub downloads, Pinecone⚠ often blocked — cache models on a personal network first

Rule of thumb

Start with 03_Core_and_Extensions — it's wired to your in-house models and offline-safe. Use the external courses' cloud providers from a personal laptop, or swap their model line for your in-house wrapper (the LangChain interface is identical).

05 Editor / how to run things

VS Code (recommended)

Install the Python + Jupyter extensions. Cmd/Ctrl+Shift+P → Python: Select Interpreter → pick your lc_env. Then: the Run button for scripts, and the notebook kernel selector (top-right of a .ipynb) must also be set to lc_env — they're separate selections.

Run a script

python 01_Models/ChatModels/chatmodel_google.py

Run a notebook

jupyter notebook          # opens a browser
# or just open the .ipynb in VS Code

Run a Streamlit app

streamlit run 02_Prompts/PromptTemplate/streamlit_PromptTemplate_ui.py

06 Verify your setup in 30 seconds

python -c "import langchain, chromadb, dotenv; print('ok', langchain.__version__)"
Observe: If that prints 'ok' and a version, your environment is ready. If an import fails, you're either outside the venv or missing that package — activate and pip install it.

LangChain version churn

LangChain's imports move between releases (e.g. langchain vs langchain_community vs langchain_openai). If an import errors, search the current LangChain docs for the class — the concept is the same, only the module path changed. Pin versions in a requirements.txt once things work.

07 A sane development workflow

  1. Activate the venv.
  2. Copy .env.example (or create .env) and fill your keys.
  3. Open the folder's GUIDE_*.html — read concepts, then follow the step-by-step.
  4. Run the smallest script/notebook first; print intermediate values.
  5. Change one thing, re-run, compare — the measure→change→re-measure habit.
  6. Commit often, but confirm .env is git-ignored before the first commit.
