01 Chapter 9 — Deployment (LangGraph Platform)

Turning an agent graph into a deployable service — this chapter is a project (src/, langgraph.json, pyproject.toml) rather than lettered snippets.

From notebook to service

langgraph.json declares your graph(s) for the LangGraph platform/CLI; src/ holds the graph code; demo.py shows calling it. This is the 'ship it' chapter.

02 What's in the folder

FileWhat it demonstrates
langgraph.jsondeclares graphs + dependencies for deployment
pyproject.tomlthe Python project + deps (Poetry-style)
src/the graph implementation to be served
demo.pyexample client calling the deployed graph

03 How to approach it

Read, then run locally

Read langgraph.json to see which graph is exposed, skim src/ for the graph definition, then use the LangGraph CLI (langgraph dev) to run it locally and hit it with demo.py. The JS side mirrors this with the JS LangGraph tooling.

langgraph.json — the deployment manifest

Python

{
  "dependencies": ["."],
  "graphs": { "agent": "./src/agent.py:graph" },
  "env": ".env"
}

JavaScript / TypeScript

// same manifest shape; graph points to the exported graph in src/
  • The manifest maps a name (agent) to the compiled graph object in your code.
  • The platform/CLI reads this to serve your graph as an API — no hand-written web server.

04 Running

LangGraph CLI

pip install langgraph-cli then langgraph dev in this folder starts a local server; open the printed URL or run python demo.py. This is a full project — expect to install its pyproject.toml deps first.

05 Takeaways

  • A LangGraph app deploys via a manifest (langgraph.json) + your graph code.
  • The CLI serves it as an API — the bridge from prototype to service.
  • Study this alongside the chatbot app in 04_external_courses/langchain_chatbot_app — two takes on deployment.
