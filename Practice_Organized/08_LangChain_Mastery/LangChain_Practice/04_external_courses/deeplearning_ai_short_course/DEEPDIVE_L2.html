L2 Deep Dive — Memory

How conversational memory really works (replaying history) and the four strategies, each with its cost/recall trade-off.

GoalBufferWindowTokenSummaryTakeaways

01 What this notebook teaches

How an LLM 'remembers' a conversation — it doesn't. Memory is just replaying past turns back into the prompt. This notebook shows four memory strategies and the cost/recall trade-off each makes.

The key realization

LLMs are stateless — each call knows nothing about the last. 'Memory' means storing prior turns and re-sending them. The question is how much to re-send: everything (accurate but expensive) or a trimmed version (cheap but forgetful).

02 ConversationBufferMemory — remember everything

code

Wire memory into a ConversationChain

from langchain.chains import ConversationChain
from langchain.memory import ConversationBufferMemory
memory = ConversationBufferMemory()
conversation = ConversationChain(llm=llm, memory=memory, verbose=True)
conversation.predict(input="Hi, my name is Andrew")
conversation.predict(input="What is my name?")
  • ConversationBufferMemory stores the full transcript.
  • Because the whole history is re-sent each call, the third turn correctly answers 'Your name is Andrew' — the model 'remembers'.
  • verbose=True prints the actual prompt so you can SEE the history being replayed — run it and watch.
code

Inspecting/loading memory directly

memory.save_context({"input": "Hi"}, {"output": "What's up"})
memory.load_memory_variables({})
  • save_context manually adds an exchange; load_memory_variables shows what's stored. This demystifies memory — it's just a growing string.

03 ConversationBufferWindowMemory — last k turns only

code

Keep only the most recent exchange

from langchain.memory import ConversationBufferWindowMemory
memory = ConversationBufferWindowMemory(k=1)  # remember 1 exchange
# ... after several turns ...
conversation.predict(input="What is my name?")
  • k=1 keeps only the last exchange. Ask for the name after other turns and the model no longer knows it — it fell outside the window.
  • Trade-off: caps token cost on long chats, at the price of forgetting older context.

04 ConversationTokenBufferMemory — a token budget

code

Trim by token count, not turn count

from langchain.memory import ConversationTokenBufferMemory
memory = ConversationTokenBufferMemory(llm=llm, max_token_limit=30)
  • Keeps as much recent history as fits in max_token_limit tokens.
  • Needs llm= because counting tokens depends on the model's tokenizer.
  • Use when you care about the actual context-window budget (tokens), not the number of turns.

05 ConversationSummaryBufferMemory — compress old turns

code

Summarize history instead of dropping it

from langchain.memory import ConversationSummaryBufferMemory
memory = ConversationSummaryBufferMemory(llm=llm, max_token_limit=100)
  • When history exceeds the limit, older turns are summarized by the LLM rather than discarded — you keep the gist without the full text.
  • Best of both: bounded token cost, but long-range context isn't lost entirely.
  • Costs extra LLM calls to produce the summaries — the trade-off here is compute, not recall.
