L4 Deep Dive — Q&A over Documents (RAG)

RAG over a catalog CSV, shown both as the one-line shortcut and the full manual pipeline it hides — load, embed, store, retrieve, stuff, generate.

01 What this notebook teaches

RAG (retrieval-augmented generation) over a real document — a 1000-row clothing catalog CSV. It shows both the one-line shortcut and the step-by-step internals of the same pipeline.

The RAG loop, in one sentence

Load documents → embed them into vectors → for a question, retrieve the closest chunks → stuff those chunks into the prompt → the LLM answers grounded in them. This is exactly what you built from scratch elsewhere; here LangChain does it in a few calls.

02 The one-line version

code

VectorstoreIndexCreator hides the whole pipeline

from langchain.document_loaders import CSVLoader
from langchain.indexes import VectorstoreIndexCreator
from langchain.vectorstores import DocArrayInMemorySearch
loader = CSVLoader(file_path="OutdoorClothingCatalog_1000.csv")
index = VectorstoreIndexCreator(
    vectorstore_cls=DocArrayInMemorySearch).from_loaders([loader])
response = index.query("Please list all shirts with sun protection...")
  • CSVLoader turns each CSV row into a Document.
  • VectorstoreIndexCreator(...).from_loaders(...) does embed + store + build-retriever in one shot; DocArrayInMemorySearch is a tiny in-memory vector store (no setup).
  • index.query(...) runs the entire retrieve-then-generate loop and returns an answer. Great for a demo — but it hides what's happening, which the next part unpacks.

03 The step-by-step version (what the one-liner does inside)

code

1) Load and 2) embed

docs = loader.load()                       # list of Documents (one per row)
from langchain.embeddings import OpenAIEmbeddings
embeddings = OpenAIEmbeddings()
embed = embeddings.embed_query("Hi my name is Harrison")
print(len(embed))     # e.g. 1536
print(embed[:5])      # first few numbers of the vector
  • embed_query turns one string into a vector; printing its length shows the embedding dimension (1536 for OpenAI's model).
  • This is the concrete 'text → numbers' step at the heart of retrieval.
code

3) Store vectors and 4) similarity-search

db = DocArrayInMemorySearch.from_documents(docs, embeddings)
query = "Please suggest a shirt with sunblocking"
docs = db.similarity_search(query)
len(docs)   # the few most similar catalog rows
  • from_documents embeds every doc and stores the vectors.
  • similarity_search embeds the query and returns the closest documents — the 'retrieval' in RAG, visible as a plain function call.
code

5) Stuff retrieved docs into the prompt, 6) generate

qdocs = "".join([docs[i].page_content for i in range(len(docs))])
response = llm.call_as_llm(
    f"{qdocs} Question: list all shirts with sun protection in a markdown table...")
  • You literally concatenate the retrieved rows and paste them before the question — this is the 'stuff' method (put everything in one prompt).
  • The LLM answers using only what you gave it → grounded output, as a markdown table.

04 RetrievalQA — the middle ground

code

A chain that wraps retrieve + stuff + generate

retriever = db.as_retriever()
qa_stuff = RetrievalQA.from_chain_type(
    llm=llm, chain_type="stuff", retriever=retriever, verbose=True)
response = qa_stuff.run(query)
  • db.as_retriever() exposes the vector store as a standard retriever object.
  • RetrievalQA packages the manual steps into one reusable chain; chain_type="stuff" = the concatenate-everything approach you just did by hand.
  • Other chain types (map_reduce, refine) handle more documents than fit in one prompt — see images/stuffmethod.png and additionalmethods.png.

05 Takeaways

  • index.query() = the whole RAG loop in one line (demo).
  • Under it: load → embed → store → similarity_search → stuff → generate.
  • RetrievalQA = that loop as a reusable chain; chain_type controls how multiple docs are combined.
Observe: This is the framework version of your from-scratch RAG. Because you built it by hand elsewhere, you now know exactly what each one-liner is doing.
