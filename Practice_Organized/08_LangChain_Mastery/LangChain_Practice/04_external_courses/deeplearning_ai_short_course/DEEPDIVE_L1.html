L1 Deep Dive — Models, Prompts, Parsers

Line-by-line: from a raw OpenAI call to LangChain's model + prompt template + output parser, and why each abstraction is worth it.

01 What this notebook teaches

The jump from calling an LLM API directly to using LangChain's three building blocks — models, prompt templates, and output parsers — and why each one earns its place.

The big idea

A raw API call works, but everything is hand-glued strings and the output is unstructured text. LangChain replaces the string-glue with reusable templates and turns free-text replies into structured Python objects you can actually use in code.

02 Part 1 — the raw OpenAI call (the 'before')

code

A plain helper around the OpenAI API

def get_completion(prompt, model="gpt-3.5-turbo"):
    messages = [{"role": "user", "content": prompt}]
    response = openai.ChatCompletion.create(
        model=model, messages=messages, temperature=0)
    return response.choices[0].message["content"]
  • messages is a list of role-tagged dicts — the chat format every modern LLM uses; here just one user turn.
  • temperature=0 makes output deterministic (same input → same output) — good for predictable tasks.
  • The reply is dug out of a nested response object as a plain string. Note: this openai.ChatCompletion.create call is the old OpenAI API (see the beginner guide — pin openai==0.28.1 or modernize).
code

The task: rewrite text in a target style using an f-string prompt

style = "American English in a calm and respectful tone"
prompt = f"""Translate the text that is delimited by triple backticks
into a style that is {style}. text: ```{customer_email}```"""
response = get_completion(prompt)
  • The prompt is assembled with a Python f-string — the variable {style} is baked in by string substitution.
  • This works, but the wording and the variables are tangled together, and you'd rewrite the whole f-string to reuse it. That pain is exactly what the template fixes next.

03 Part 2 — the same thing with LangChain

code

The model wrapper

from langchain.chat_models import ChatOpenAI
chat = ChatOpenAI(temperature=0.0)
  • ChatOpenAI is LangChain's uniform chat-model object. Swap this one line for ChatAnthropic etc. and everything else stays the same.
  • (Modern import: from langchain_openai import ChatOpenAI.)
code

A prompt template — wording and variables kept separate

template_string = """Translate the text ... into a style that is {style}.
text: ```{text}```"""
from langchain.prompts import ChatPromptTemplate
prompt_template = ChatPromptTemplate.from_template(template_string)
  • {style} and {text} are declared slots, not yet filled.
  • prompt_template.messages[0].prompt.input_variables lists those slots — LangChain parsed them out for you, and will error if you forget one at fill time.
  • The template is now a reusable object — fill it many times with different values.
code

Fill the template, then call the model

customer_messages = prompt_template.format_messages(
        style=customer_style, text=customer_email)
customer_response = chat(customer_messages)
print(customer_response.content)
  • format_messages(...) returns a list of message objects (a HumanMessage) — the chat format, built for you from the template.
  • chat(messages) calls the model; the reply is an AIMessage whose .content is the text.
  • Reuse: the same prompt_template is immediately reused to rewrite a support reply in 'English pirate' style — that reuse is the whole point of templates.

04 Part 3 — output parsers (text → Python dict)

code

Why you need a parser

response.content            # a STRING that LOOKS like JSON
response.content.get('gift')  # ERROR: strings have no .get()
  • Even when you ask the model for JSON, response.content is still a string. Calling .get() on it fails — it's not a dict yet.
  • You could json.loads() it, but the model sometimes adds stray prose that breaks that. A structured parser handles this robustly.
code

Define the schema you want back

from langchain.output_parsers import ResponseSchema, StructuredOutputParser
gift_schema = ResponseSchema(name="gift", description="...True if a gift...")
output_parser = StructuredOutputParser.from_response_schemas(response_schemas)
format_instructions = output_parser.get_format_instructions()
  • Each ResponseSchema declares one field you want (name + description).
  • get_format_instructions() auto-generates text telling the model EXACTLY how to format its answer — you paste this into the prompt.
  • This is the trick: you tell the model the shape, then the parser can reliably read it back.
code

Fill prompt with the format instructions, then parse

messages = prompt.format_messages(text=customer_review,
                                  format_instructions=format_instructions)
response = chat(messages)
output_dict = output_parser.parse(response.content)
output_dict.get('delivery_days')   # now this WORKS — it's a real dict
  • The prompt now carries the format instructions, so the model returns clean, parseable output.
  • output_parser.parse(...) converts the reply string into a genuine Python dict — now .get('delivery_days') works.
  • This is the payoff of the whole notebook: unstructured text became structured data your program can use.

05 Takeaways

  • Model = the uniform wrapper (swap providers in one line).
  • PromptTemplate = reusable prompt with named slots + validation.
  • OutputParser = turn the reply into a Python object.
