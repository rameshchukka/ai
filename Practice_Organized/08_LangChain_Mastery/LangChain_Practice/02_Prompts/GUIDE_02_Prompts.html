01 Concepts you need first

Templates, not string concatenation

A PromptTemplate holds fixed wording with {placeholders} you fill at call time. Benefits: reuse, validation (it checks you supplied every variable), and safe injection of user data. You'll feel the difference against the f-string version in this folder.

Chat = a list of role-tagged messages

Chat models take a sequence of messages, each with a role: system (sets behavior), human (the user turn), AI (a prior model reply). ChatPromptTemplate templates that whole list. Getting roles right is most of getting chat behavior right.

03 Walkthrough — PromptTemplate

exercise

fstringexample.py → Withformatstring.py → prompt_template.py

Concept — the progression: the same task done three ways, worst to best. f-string (brittle, inline), format string (a little better), then a real PromptTemplate (reusable, validated).

Steps: run all three; note they produce the same filled prompt but the template version keeps wording and inputs separate.

✔ Worked answer / expected output

All three print the same final prompt text. The template version additionally errors helpfully if you forget a variable — try removing one input to see the validation. That safety is why templates win in real code.

exercise

Create_template_json.py + template.json

Concept: save a prompt template to disk (template.json) and reload it — so prompts are versioned artifacts, not buried in code.

✔ Worked answer / expected output

Writes/loads template.json; the reloaded template fills identically to the in-code one. Open the JSON to see the template string and its declared input variables.

exercise

temperature_param.py

Concept: how temperature changes generation on the same prompt.

✔ Worked answer / expected output

Low temperature → focused, repeatable answers; high temperature → more varied, creative wording. Run twice at each setting to feel the difference.

exercise

streamlit_PromptTemplate_ui.py

Concept: wrap a template in a tiny web UI. Run with streamlit run.

✔ Worked answer / expected output

Opens a local web page with an input box; typing fills the template and calls the model, showing the reply. Your first interactive LLM app.

04 Walkthrough — ChatPromptTemplate

exercise

00_chat_Messages.py

Concept: construct SystemMessage, HumanMessage, AIMessage objects and send them to a chat model.

✔ Worked answer / expected output

The model's reply reflects the system message's instruction. Change the system message (e.g. 'reply like a pirate') and the whole tone shifts — proof that the system role steers behavior.

exercise

01_ChatHistory_messages_static.py

Concept: a fixed multi-turn conversation passed as a message list, so the model has context from earlier turns.

✔ Worked answer / expected output

The model answers the latest turn using the earlier ones — e.g. a follow-up like 'and its capital?' resolves because the prior turn named a country.

exercise

02_chatPromptTemplate_Dynamic.py

Concept: a ChatPromptTemplate with variables, so the message list is generated from inputs rather than hardcoded.

✔ Worked answer / expected output

Filling the template with different variable values produces different chat prompts from the same structure — reusable chat prompting.

capstone

03_ChatPromptTemp_messages_history.py

Concept — the chatbot foundation: a template plus a running history placeholder, so each new user turn is appended and the model always sees the full conversation.

✔ Worked answer / expected output

A multi-turn exchange where each reply accounts for everything said before. This is the pattern every chatbot uses; notebook 03/05 in 03_Core_and_Extensions builds on it.
