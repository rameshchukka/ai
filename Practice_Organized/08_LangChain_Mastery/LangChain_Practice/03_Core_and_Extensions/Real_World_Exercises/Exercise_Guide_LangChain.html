📘 Concept Notes

What LangChain abstracts

LangChain packages the repeated plumbing of LLM apps — prompt templating, chaining steps together, memory, and tool-calling — into reusable, composable building blocks.

LCEL (`|` composition)

The pipe operator composes a pipeline: `prompt | model | parser` means 'fill in the prompt, send it to the model, then parse the raw output' — each stage has one clear responsibility.

Memory strategies

A buffer memory keeps the full conversation verbatim (accurate but grows unbounded in token cost). A summary memory compresses older turns. Real apps pick a strategy deliberately based on conversation length and cost tolerance.

Tools and agent tool-selection

A tool's docstring is the *only* signal an agent uses to decide when to call it. Vague descriptions cause the wrong tool to be picked; precise, intent-specific descriptions fix this.

💡 Tips & Pitfalls

Tips

  • Start without LangChain (plain API calls) to understand what it's abstracting, then adopt it as complexity grows.
  • Keep chains small and composable — a 200-line single chain is a debugging nightmare.
  • Give tools clear, narrow docstrings — tool-selection quality depends entirely on them.

Common Pitfalls

  • Over-engineering a single-prompt task into a full agent (adds latency/cost/failure surface for no benefit).
  • Not capping agent iterations — a confused agent can loop indefinitely.
  • Version drift: LangChain's API changes fast; pin versions and read release notes.
