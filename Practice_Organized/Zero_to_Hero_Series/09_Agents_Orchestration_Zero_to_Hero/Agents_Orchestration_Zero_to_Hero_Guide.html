Agents & Orchestration: Zero to Hero

The ReAct loop, tool selection, memory, loop safety, approval gates, and multi-agent orchestration — from first principles.

📘 Concept Notes

Agents decide their own path

A chain runs a fixed sequence; an agent looks at the goal and current state and chooses the next action, looping until done. Use agents when the number of steps or the tools needed depend on intermediate results.

ReAct is the core loop

Agents alternate Reasoning (which tool and input?) and Acting (run the tool), feeding each Observation back into the next reasoning step. A running scratchpad of steps-so-far is what makes multi-step reasoning work.

Tool descriptions drive selection

When an agent picks the wrong tool, the fix is almost always a clearer tool description, not a bigger model. Each description should state exactly when to use the tool and what input it needs.

Safety is not optional

A confidently-wrong agent can loop forever and burn your whole budget. Real agents need step caps, repeat detection, cost/time budgets, fail-closed defaults, and human approval gates on irreversible actions.

💡 Tips & Pitfalls

Tips

  • Always bound the loop with max_steps AND a cost/time budget.
  • Fix wrong tool choices with better descriptions first.
  • Log every step — agent bugs are invisible without a trace.

Common Pitfalls

  • No stopping condition -> infinite loops that burn budget.
  • Fail-open approval (acting without a human) on sensitive tools.
  • Reaching for multi-agent when one agent would do (cost + error cascades).

🌍 Real-World Use Cases
