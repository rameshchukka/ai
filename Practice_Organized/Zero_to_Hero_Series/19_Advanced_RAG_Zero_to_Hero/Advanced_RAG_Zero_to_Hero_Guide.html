Advanced RAG: Zero to Hero

Query rewriting, re-ranking, HyDE, multi-hop retrieval, routing, compression, and self-correction.

📘 Concept Notes

Basic RAG fails in predictable ways

Vocabulary mismatch (query and document mean the same thing but share no words), multi-hop questions (the answer needs facts from several documents), and noisy top-k results (irrelevant chunks diluting the context) are the three classic failure modes basic retrieve-then-generate RAG doesn't handle.

Retrieve wide, re-rank narrow

A bi-encoder (query and document embedded separately) is fast but approximate. A cross-encoder (query and document scored together) is far more accurate but too slow for the whole corpus. Production systems retrieve a wide candidate set cheaply, then re-rank just those with the accurate method.

HyDE flips the retrieval direction

Instead of embedding a short, sparse query, HyDE asks an LLM to first write a plausible hypothetical answer, then embeds and searches with THAT — because a generated answer's vocabulary tends to be much closer to real documents than the original question's wording.

Not every query needs the same strategy

Query routing classifies the incoming query first and picks the retrieval path that fits: simple factual lookups use standard retrieval, compound questions use multi-hop decomposition, short/vague queries use HyDE.

💡 Tips & Pitfalls

Tips

  • Documents retrieved by multiple query variants are a strong relevance signal.
  • Only run a cross-encoder over a small candidate set, never the whole corpus.
  • Always bound self-correction retries with a graceful 'I don't know' fallback.

Common Pitfalls

  • Running an expensive cross-encoder over the entire corpus.
  • Retrieving once for a compound question and getting only half an answer.
  • Trusting HyDE's hypothetical answer blindly when it might be confidently wrong.

🌍 Real-World Use Cases

  • Production RAG systems answering compound, multi-part questions
  • Support/knowledge-base search where query wording rarely matches documents
  • Any RAG system that needs to know when NOT to answer
