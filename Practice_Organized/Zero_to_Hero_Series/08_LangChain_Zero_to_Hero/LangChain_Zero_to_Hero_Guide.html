LangChain: Zero to Hero

Runnables, the pipe operator (LCEL), prompt templates, chains, parsers, memory, tools, and agents — built from first principles.

📘 Concept Notes

Everything is a Runnable

LangChain's core abstraction is the Runnable: anything with an .invoke(input) method. Because prompts, LLMs, parsers, retrievers, and tools all share this interface, you can pipe them together with the | operator into chains.

LCEL is just piping

LangChain Expression Language (LCEL) is the | operator you already know from Unix pipes. prompt | llm | parser reads left to right: fill the template, feed it to the model, parse the result. This linear pipe covers most real apps.

Chains are fixed paths; agents decide the path

A chain always runs the same sequence of steps. An agent uses the LLM as a router to decide which tool to call at runtime. That flexibility is powerful but less predictable — hence the need for guardrails.

Memory and retrieval are add-on Runnables

Stateful conversation is just a component that stores history and injects it into the prompt. RAG is just a retriever Runnable feeding context into the prompt. Both slot into the same pipe pattern.

💡 Tips & Pitfalls

Tips

  • Keep each Runnable single-purpose so it's testable and reusable.
  • The | you learn here is the exact operator real LangChain uses.
  • Give tools crisp descriptions — agents pick tools from those words.

Common Pitfalls

  • Forgetting to escape literal braces {{ }} in templates.
  • Passing a dict whose keys don't match the template variables.
  • Unbounded memory overflowing the context window.

🌍 Real-World Use Cases

  • Composable LLM pipelines (prompt->llm->parser)
  • Chatbots with memory and retrieval
  • Tool-using agents over calculators, search, and databases
