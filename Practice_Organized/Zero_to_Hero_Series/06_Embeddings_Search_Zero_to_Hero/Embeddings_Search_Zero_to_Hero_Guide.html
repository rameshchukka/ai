Embeddings & Search: Zero to Hero

From bag-of-words to BM25 to semantic and hybrid search — built from first principles and evaluated with real metrics.

📘 Concept Notes

Every search method is a scoring function

Search means ranking documents by relevance. Each method (TF-IDF, BM25, embeddings) is just a different score(query, doc) function; everything else is plumbing around sorting by that score.

Cosine similarity compares direction, not length

Cosine similarity measures the angle between two vectors, ignoring magnitude. That's why a short and a long document on the same topic still score as similar — they point the same way in vector space.

Keyword vs semantic

TF-IDF/BM25 match shared spellings (great for exact terms, codes, names). Embeddings match meaning, so 'money back' finds a 'refund' document with zero shared words. Hybrid search fuses both strengths.

Chunking and evaluation are not optional

Real documents must be chunked (with overlap) before embedding. And 'looks good' is not a metric — measure precision@k, recall@k, and MRR against a small labeled set to actually know if your search works.

💡 Tips & Pitfalls

Tips

  • TF-IDF/BM25 is a strong, fast baseline — start there.
  • BM25 defaults k1=1.5, b=0.75 are battle-tested.
  • Always eyeball top-k results before trusting a metric.

Common Pitfalls

  • Bag-of-words ignores word order and meaning.
  • Comparing embeddings from two different models (different spaces).
  • Chunking mid-sentence and destroying meaning.

🌍 Real-World Use Cases

  • Knowledge-base / FAQ semantic search
  • 'Find similar products/documents' features
  • The retrieval stage of a RAG pipeline
