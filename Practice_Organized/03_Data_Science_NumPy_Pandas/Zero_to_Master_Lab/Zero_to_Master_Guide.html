📘 Concept Notes

What this lab is

Two self-contained notebooks that take you from total beginner to confident, job-ready use of NumPy and Pandas. Every concept has theory, a worked example, an exercise, and a solution — all inside the .ipynb files, using real bundled datasets.

Why NumPy first, then Pandas

Pandas is built directly on top of NumPy. The vectorization, broadcasting, and indexing ideas you learn in the NumPy lab are the exact foundation Pandas uses — so doing NumPy first makes Pandas click far faster.

Learn on messy, real data

The Pandas lab uses a 1,010-row retail sales dataset with deliberate real-world problems: missing values, duplicate rows, and inconsistent text casing. You'll clean it and analyze it as you learn — not toy data that's already perfect.

The split-apply-combine mindset

The single most important Pandas skill is groupby: split data into groups, apply a summary to each, combine the results. It answers every 'X by Y' business question and is covered in depth in Chapter 9 of the Pandas lab.

💡 Tips & Pitfalls

Tips

  • Type the code yourself — don't just read it. Muscle memory matters.
  • If you're about to write a for-loop over an array/column, pause: there's almost always a vectorized way.
  • Run the inspection ritual (info, describe, isna().sum()) the moment you load any dataset.
  • Do NumPy before Pandas — the second builds directly on the first.

Common Pitfalls

  • Skipping the 'Your Turn' exercises and only reading solutions — you won't retain it.
  • Confusing .loc (label-based, inclusive slice) with .iloc (position-based, exclusive slice).
  • Forgetting .copy() on a filtered slice, then being surprised the original changed.
  • Forgetting parse_dates when loading CSVs, so date columns stay as strings.
