📘 Concept Notes

Tensors

A tensor is PyTorch's array type — like a NumPy array, but it can live on a GPU and can track operations for automatic differentiation (autograd).

Autograd

When a tensor has `requires_grad=True`, PyTorch records every operation applied to it. Calling `.backward()` walks that record backward (the chain rule) to compute the gradient of a loss with respect to every parameter.

The training loop

Every PyTorch model trains the same way: forward pass (compute predictions) → compute loss → `loss.backward()` (compute gradients) → `optimizer.step()` (update weights) → `optimizer.zero_grad()` (reset gradients for next batch).

DataLoader & batching

Training on the whole dataset at once is often impractical. `DataLoader` splits data into shuffled mini-batches so training is both memory-efficient and less prone to learning spurious order effects.

💡 Tips & Pitfalls

Tips

  • Always call optimizer.zero_grad() before backward() — gradients accumulate otherwise.
  • Normalize inputs; unscaled inputs are a common reason a model won't learn at all.
  • Use model.eval() + torch.no_grad() for validation/inference.

Common Pitfalls

  • Forgetting .item() when logging a loss tensor (keeps the whole graph alive — a memory leak).
  • Learning rate too high (NaN loss) or too low (loss barely moves).
  • Not shuffling training data, letting the model learn order artifacts.
