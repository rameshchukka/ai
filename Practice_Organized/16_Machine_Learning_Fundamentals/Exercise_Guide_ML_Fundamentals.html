📘 Concept Notes

Train/test split

You must evaluate a model on data it never saw during training — otherwise you're measuring memorization, not generalization. A held-out test set (or cross-validation) is non-negotiable.

Choosing the right metric

Accuracy alone can be misleading, especially on imbalanced problems (e.g., rare churn events). Precision (of predicted positives, how many were right), recall (of actual positives, how many were caught), and F1 (their balance) tell a fuller story.

Baseline before complexity

Always fit a simple model (logistic regression) first. It's fast, interpretable, and tells you whether a complex model is actually earning its added complexity.

Tree ensembles on tabular data

Random forests (and gradient boosting) are usually the strongest baseline on tabular business data, and — unlike distance-based or linear models — don't require feature scaling.

💡 Tips & Pitfalls

Tips

  • Always start with a simple baseline model before reaching for something complex.
  • Cross-validation gives a more reliable performance estimate than a single train/test split.
  • Scale features for distance-based models (KNN, k-means); tree models don't need it.

Common Pitfalls

  • Data leakage: information from the test set (or the future) sneaking into training.
  • Evaluating only on training data and being surprised by poor real-world performance.
  • Choosing accuracy as the only metric on an imbalanced classification problem.
