📘 Concept Notes

Tokens, not words

Text is broken into tokens (often sub-word pieces) before an LLM processes it. Token count drives both cost and context-window usage, and doesn't map 1:1 to word count — this trips up beginners constantly.

Self-attention, intuitively

For each token, self-attention computes how much it should 'attend to' (be influenced by) every other token, based on learned similarity between Query and Key vectors, then produces a weighted average of Value vectors — this is how a Transformer builds contextual meaning.

Sampling and temperature

After scoring candidate next-tokens, the model converts scores to a probability distribution (softmax) and samples from it. Temperature reshapes that distribution: low temperature sharpens it toward the top choice (deterministic); high temperature flattens it (more random/diverse).

Adaptation strategies

You can adapt a pretrained model to a task via prompting (cheapest, fastest to iterate), RAG (grounds it in your data), or fine-tuning (most expensive, usually a last resort) — try them roughly in that order.

💡 Tips & Pitfalls

Tips

  • 'Attention' is just a learned weighting of how much each token should influence each other token.
  • More tokens in context isn't free — cost and sometimes accuracy both suffer with very long contexts.
  • Try prompting and RAG before fine-tuning; they're cheaper and faster to iterate on.

Common Pitfalls

  • Treating token count and word count as the same thing.
  • Assuming a bigger/newer model automatically fixes a prompting or architecture problem.
