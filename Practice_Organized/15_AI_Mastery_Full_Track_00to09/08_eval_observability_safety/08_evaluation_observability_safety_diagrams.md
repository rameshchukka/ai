# Module 8 — Diagrams

## 1. Evaluation pipeline

```
  Golden test set
  [(question, expected_context_or_answer), ...]
              |
              v
   ┌─────────────────────┐
   │  Run through system   │  (retrieval + generation, your actual pipeline)
   └─────────┬───────────┘
              v
        candidate answers
              |
              v
   ┌─────────────────────┐
   │  Judge model scores    │  faithfulness, relevance, etc. per item
   └─────────┬───────────┘
              v
        aggregate scores
              |
              v
     compare against last run's
     scores -> regression detected?
```

## 2. Trace / span hierarchy (observability)

```
  Trace: request_id=abc123
   │
   ├── Span: query_rewrite      (latency: 120ms)
   │
   ├── Span: retrieval           (latency: 80ms)
   │     └── chunks returned + scores logged
   │
   ├── Span: rerank              (latency: 200ms)
   │
   ├── Span: generation          (latency: 900ms)
   │     └── full prompt + model + params logged
   │
   └── Span: final_output        logged
```

## 3. Self-preference bias in LLM-as-judge

```
   Candidate answer generated by: MODEL_QWEN3_14B
              |
              v
   Judged by: MODEL_QWEN3_14B  -> score: 95%   (same family,
                                                  less skeptical)
   Judged by: MODEL_LLAMA       -> score: 78%   (different family,
                                                  more reliable signal)

   Rule of thumb: judge model should be a DIFFERENT family/tier
   than the model being evaluated.
```

## 4. Guardrail testing as an explicit checklist, not an assumption

```
   [ ] Prompt injection via retrieved content   -> tested?
   [ ] PII echoed back inappropriately          -> tested?
   [ ] Refusal correctness (harmful requests)   -> tested?
   [ ] Refusal correctness (benign requests,    -> tested?
       NOT over-refusing)
   [ ] Jailbreak rephrasing resistance           -> tested?

   "It seemed fine in the demo" is not the same as "tested."
```
