📘 Concept Notes

The ReAct pattern

Reason (decide what to do) → Act (call a tool) → Observe (read the result) → repeat until a final answer is ready. This loop is what 'agent' means in most frameworks — the framework just automates the reasoning step with an LLM call.

Why a step limit is mandatory

An agent that's confused or stuck in ambiguous reasoning can loop forever without a hard cap — every real agent implementation needs a max_steps guard and a fallback message.

Human-in-the-loop approval

Irreversible or costly actions (refunds, purchases, sending messages) should never fire automatically — gate them behind an explicit approval step, human or otherwise.

Handling ambiguity

A good agent asks a clarifying question rather than guessing when required information (like an order number) is missing — guessing produces confidently wrong actions.

💡 Tips & Pitfalls

Tips

  • Give the agent a maximum step count and a fallback message — never let it run unbounded.
  • Make tool errors return a clear string the model can read and react to, not a raw stack trace.
  • Log every reasoning/action/observation step during development.

Common Pitfalls

  • Ambiguous tool descriptions causing the wrong tool to be picked.
  • No approval gate before an irreversible action.
  • Treating agent output as ground truth without a verification step.

🌍 Real-World Use Cases

  • An eligibility/approval workflow that gathers data via tools then asks a human to confirm
  • A research agent that searches, retrieves, and drafts a report
