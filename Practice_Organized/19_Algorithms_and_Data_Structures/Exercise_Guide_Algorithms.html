📘 Concept Notes

Big-O — why it matters practically

Big-O describes how an algorithm's runtime/memory grows as input size grows. An O(n^2) solution that's fine for 100 items can be unusably slow for 1,000,000 — this is the difference that shows up in real production incidents.

Hash maps as the universal speedup

Whenever a problem involves 'have I seen this before' or 'count occurrences', a hash map (dict/set) turns an O(n^2) nested-loop solution into an O(n) single-pass solution.

Binary search on sorted data

If your data is sorted, binary search (O(log n)) beats scanning (O(n)) dramatically as data grows — Python's `bisect` module implements this for you.

Dynamic programming = memoized recursion

When a recursive solution recomputes the same subproblem many times (like naive Fibonacci), caching each subproblem's result (memoization) turns exponential time into linear or polynomial time.

💡 Tips & Pitfalls

Tips

  • Get a correct brute-force solution working before optimizing.
  • A hash map turns most 'have I seen this before' problems into O(n).
  • If a problem mentions 'shortest path' or 'connected components', think graph + BFS/DFS.

Common Pitfalls

  • Ignoring the space complexity of a recursive solution's call stack.
  • Reaching for a complex algorithm when a simpler O(n log n) sort + scan solves it.
