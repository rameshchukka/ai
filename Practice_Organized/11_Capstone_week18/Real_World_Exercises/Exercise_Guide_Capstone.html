📘 Concept Notes

Why scoping is a skill

Real stakeholder requests are almost always vague ('build something with AI to help'). Translating that into a scoped, buildable project — before writing any code — is the difference between a project that ships and one that drifts forever.

Discovery questions

Good discovery questions surface volume, current process, success metrics, risk tolerance, and integration constraints — the things that determine feasibility and scope, not just 'what do you want it to do'.

The MVP cut

An MVP isn't a smaller, worse version of the final product — it's the smallest slice that proves or disproves the core idea, deliberately excluding nice-to-haves.

Naming risks up front

Every AI project has unknowns (data quality, cost at scale, integration surprises). Naming them explicitly with a mitigation, rather than discovering them mid-build, is what separates a plan from a wish.

🧭 Beginner → Expert Roadmap

1

Beginner

  • Can list discovery questions before jumping to a solution
  • Distinguishes must-have from nice-to-have features
  • Writes a one-paragraph MVP scope for a given ask
2

Intermediate

  • Identifies concrete risks and pairs each with a mitigation
  • Chooses success metrics tied to business outcomes, not vanity metrics
  • Sketches a basic architecture (ingestion → processing → serving)
3

Expert

  • Runs a full stakeholder discovery conversation and synthesizes it into a scoping doc
  • Balances technical feasibility against business urgency in scope decisions
  • Plans evaluation/guardrails work into the project timeline from day one

💡 Tips & Pitfalls

Tips

  • Ask about failure cases and edge cases in discovery, not after building.
  • Write the MVP cut before writing any code — it's a scoping tool, not an afterthought.
  • Budget for evaluation and guardrails work in your plan, not just the 'happy path' build.

Common Pitfalls

  • Scope creep from skipping a clear MVP cut.
  • Underestimating integration/data-cleaning work vs. the 'interesting' modeling work.
  • No plan for how you'll know the system is working after launch.
